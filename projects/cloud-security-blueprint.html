PROJECT 04 / CLOUD SECURITY

Cloud Security Operations Blueprint

A governed AWS reference design connecting business requirements to architecture, controls, ownership, testing, evidence, and monitoring.

The Problem

A fictional logistics company is considering moving its dispatch and delivery platform to AWS. The design must protect customer and potentially sensitive medical-delivery information while keeping time-sensitive dispatch available and responsibilities clear.

My Approach

I followed one trace throughout the design: business requirement → risk → architecture decision → control → owner → test → evidence → monitoring. The blueprint separates production and nonproduction, distinguishes AWS administration from application access, and defines logging, response, recovery, and assurance.

What I Built

Eighteen core documents covering context, scope, inventory, data flows, risk, shared responsibility, AWS architecture, IAM, protection, monitoring, incident response, resilience, testing, metrics, exceptions, and executive reporting, plus a control matrix, crosswalk, standards, procedures, templates, sample evidence, and diagrams.

Methods: AWS · NIST CSF 2.0 · AWS Well-Architected · Cloud GRC · Shared Responsibility
